# Проверочный лист безопасности бизнес-систем PropDevelopment

Значения в колонке «Да/нет»: **Да**, **Нет**, **Частично**, **Нет данных** (из описания системы не следует, проверить в ходе аудита).
Выбор разделов обоснован в [README.md](README.md). Раздел V.2 (физическая безопасность) исключён, разделы VI и VII добавлены.

| №   | Вопрос | Да/нет | Комментарий |
| --- | --- | --- | --- |
| **I. Управление доступом** | | | |
| 1   | Используется ли многофакторная аутентификация (MFA) для доступа к критическим системам и сервисам? | Нет данных | Клиенты и собственники аутентифицируются в auth-service-1 (Keycloak), сотрудники — в Active Directory. Использование MFA не описано. Нужна MFA для сотрудников с доступом к CRM, DWH, финансам и онлайн-сделке, а также для подтверждения сделки и команд «Умного дома» в приложении. |
| 2   | Настроены ли требования к сложности паролей и их регулярное обновление? | Нет данных | Проверить парольные политики в Keycloak (auth-db-1) и в обоих экземплярах Active Directory. |
| 3   | Проводится ли аудит и пересмотр учётных записей с повышенными привилегиями на регулярной основе? | Нет | После смены руководителей IT-команд нарушена передача информации, а специалист по ИБ один на всю компанию. Регулярный пересмотр привилегий не организован. |
| 4   | Реализован ли принцип минимальных привилегий при назначении ролей и прав доступа? | Нет | Со стороны систем обработки данных (DWH, BI) нет ограничений на доступ к данным. API партнёров позволяют одной УК видеть и изменять данные клиентов и ЖК другой УК. |
| 5   | Автоматически ли удаляются или деактивируются учётные записи после увольнения или изменения должности сотрудников? | Нет данных | Учётные записи ведутся в нескольких независимых каталогах (два Active Directory, Keycloak, auth-db-1 финансов). Без единого реестра автоматическая деактивация во всех системах маловероятна. |
| 6   | Ведётся ли журналирование всех операций доступа к системам и данным? Кто имеет доступ к журналам? | Нет данных | Централизованное журналирование не описано. Для анализа ошибки с чужими ФИО в личном кабинете нужны журналы доступа к ПДн. |
| 7   | Используются ли механизмы контроля доступа на основе атрибутов для повышения гибкости управления доступом? | Нет | Доступ партнёров не ограничивается атрибутом «управляющая компания» или «ЖК», поэтому данные УК не изолированы друг от друга. Нужен ABAC (tenant_id, ЖК, класс данных). |
| 8   | Используются ли системы аутентификации пользователей для доступа к системам? | Да | auth-service-1 (Keycloak) для клиентов и собственников, Active Directory для менеджеров, бизнес-аналитиков и бухгалтеров. |
| 9   | Созданы ли замкнутые контуры для подсистем, работающих с чувствительными данными? | Частично | Финансовый домен выделен в отдельный контур со своим Active Directory. CRM, client-mart-db (паспортные данные, сделки) и DWH с сырыми ПДн в замкнутые контуры не выделены. |
| 10  | Ограничен ли доступ к системам из внешних источников? | Частично | Клиенты и собственники входят через межсетевой экран. Исходящие и входящие интеграции с API управляющих компаний идут без единых политик безопасности. |
| 11  | Ведётся ли единый реестр учётных записей? | Нет | Учётные записи хранятся в Keycloak (auth-db-1), двух Active Directory и auth-db-1 финансового сервиса. Клиент регистрируется в нескольких точках (витрина, client-crm-app, приложение собственника) без координации. |
| 12  | Используются ли средства управления учётными записями на базе единого реестра? | Нет | Следует из п. 11. Рекомендуется IdM/IGA и единый IdP: Keycloak как SSO для клиентов, федерация с Active Directory для сотрудников. |
| 13  | Применяются ли средства для отзыва прав доступа? | Нет данных | Проверить процедуру отзыва ролей в Active Directory и Keycloak, а также отзыв токенов и ключей API партнёров. |
| 14  | Используются ли средства централизованного контроля доступа? | Нет | Права настраиваются в каждой системе отдельно, единой точки политик (API Gateway, PDP) нет. |
| **II. Безопасность данных** | | | |
| 1   | Разработана ли политика классификации данных, и актуализируется ли она в соответствии с действующим законодательством? | Нет | Ограничения на передачу данных определяются бизнес-процессами, а не классом данных. Классификация предложена в Task1, её нужно утвердить как политику. |
| 2   | Используется ли шифрование на уровне базы данных, файловой системы и при передаче данных по сети? | Нет данных | Межсервисный обмен идёт по REST, JDBC, Kafka и CDC, использование TLS не описано. Нужно проверить TLS на всех каналах, шифрование client-mart-db (паспортные данные) и S3 DWH. |
| 3   | Реализованы ли механизмы управления ключами шифрования? | Нет данных | Хранилище секретов (Vault, KMS) не описано, а ключи и токены API партнёров — секретные данные. |
| 4   | Проводится ли регулярное резервное копирование данных? Хранятся ли резервные копии в защищённых хранилищах? | Частично | Резервное копирование выполняется для всех БД на нужную глубину. Защищённость хранилищ копий не описана. |
| 5   | Выполняется ли регулярное тестирование процесса восстановления данных из резервных копий? | Нет данных | Проверить наличие регулярных тестовых восстановлений и их результаты (RPO, RTO). |
| 6   | Ограничен ли доступ к резервным копиям данных, и зашифрованы ли они? | Нет данных | Копии содержат ПДн и паспортные данные, поэтому их нужно шифровать и ограничить к ним доступ. |
| 7   | Ведётся ли учёт персональных данных, и применяются ли специальные процедуры обработки и хранения для различных типов данных? | Нет | Контракты API партнёров содержат ПДн, сырые данные с ПДн по CDC попадают в DWH без отдельных процедур. Реестр ПДн, цели и сроки обработки по 152-ФЗ не описаны. |
| 8   | Осуществляется ли мониторинг доступа к данным на основе их классификации? Используются ли метки безопасности для маркировки данных? | Нет | Классификации нет, значит, нет и меток. Внутренние потоки данных контролируются не системно. |
| 9   | Разработаны ли процессы и системы Data Governance для управления данными? | Нет | Проблема управления и хранения потоков данных блокирует продукты на BI, ML и AI. Нужны каталог данных, владельцы данных и lineage. |
| 10  | Реализованы ли системы или процессы безопасного уничтожения данных? | Нет данных | Проверить удаление ПДн по истечении целей обработки и по отзыву согласия (152-ФЗ), в том числе в DWH и резервных копиях. |
| 11  | Используются ли системы или процессы контроля целостности данных? | Нет | В личном кабинете отображаются данные другого клиента. Это признак нарушения целостности или ошибочного связывания записей. Несколько несогласованных точек регистрации создают дубли. |
| 12  | Реализованы ли системы или процессы контроля сохранности данных? | Частично | Резервное копирование есть. Контроль сохранности при передаче партнёрам и в DWH (сверки, контрольные суммы) не описан. |
| 13  | Применяются ли средства или процессы анонимизации данных? | Нет | В DWH передаются сырые данные по CDC без обезличивания, а доступ к DWH не ограничен. Для BI, ML и AI нужны псевдонимизация и маскирование ПДн. |
| 14  | Разработана ли инструкция по процессу восстановления данных? | Нет данных | Проверить наличие DR-плана и инструкций для каждой БД. |

В Kubernetes изоляцию обеспечивают NetworkPolicy (см. Task5). |

| 5   | Проводится ли регулярное сканирование уязвимостей операционных систем, приложений и сетевых устройств? | Нет данных | |
| 6   | Установлены ли на серверах и рабочих станциях антивирусные программы и системы EDR? | Нет данных | |

| 8   | Используются ли механизмы контроля целостности системных файлов? Ведётся ли журналирование доступа к системным ресурсам? | Нет данных | |
| 9   | Проводятся ли автоматизированные сканирования облачных инфраструктур на соответствие рекомендациям безопасности? | Нет | Команды сами используют облачные ресурсы и управляемые сервисы для доработки и тестирования, а специалисту по ИБ передают не все изменения. Облачный контур не контролируется (риск shadow IT и тестов на реальных ПДн). |

| 12  | Используются ли средства для контроля периметра доступа? | Частично | Межсетевой экран для внешних пользователей есть. Периметр для партнёрских API (API Gateway) отсутствует. |
| **IV. Управление инцидентами** | | | |
| 1   | Используется ли система мониторинга безопасности (SIEM) для корреляции событий и анализа аномалий в режиме реального времени? | Нет данных | В описании SIEM нет, а один специалист по ИБ не может анализировать события вручную. |
| 2   | Настроены ли автоматические оповещения об инцидентах и подозрительной активности (например, попытках несанкционированного доступа)? | Нет данных | Жалобы на чужие ФИО компания узнаёт от клиентов, а не от систем мониторинга. |
| 3   | Разработан ли план реагирования на инциденты, включающий анализ, эскалацию и восстановление системы? Проводится ли обучение сотрудников? | Нет | Утечка у конкурента вызвала обеспокоенность руководства, значит, готового плана нет. По 152-ФЗ об инциденте с ПДн нужно уведомить Роскомнадзор в течение 24 часов, о результатах расследования — в течение 72 часов. |
| 4   | Проводятся ли симуляции инцидентов (учения) для проверки готовности сотрудников к реагированию на кибератаки? | Нет данных | |
| 5   | Ведётся ли статистика по всем зарегистрированным инцидентам и используются ли результаты анализа для корректировки политики безопасности? | Нет данных | |
| 6   | Как часто проводятся внутренние и внешние аудиты безопасности? Обновляются ли политики и процедуры на основе результатов этих аудитов? | Нет | Комплексный аудит безопасности проводится впервые, сейчас к нему идёт подготовка. |

| **V.1. Общие вопросы** | | | |

Приложение собственников — клиентское, для него нужны защита API, certificate pinning и проверка целостности приложения. |
| 2   | Настроены ли VPN и шифрование для безопасного удалённого доступа к корпоративным ресурсам? | Нет данных | Нужно также проверить защищённые каналы между ЦОД, приватным облаком и облачным провайдером. |
| 3   | Проводится ли автоматическое выявление и ограничение использования незарегистрированных или неавторизованных устройств в сети? | Нет данных | |
| 4   | Настроены ли политики автоматического резервного копирования в облачной среде? Контролируется ли доступ к резервным копиям? | Нет данных | Часть продуктов работает в гибридной среде. Нужно проверить, что копии БД в облаке попадают под ту же политику, что и в ЦОД. |
| **VI. Интеграции и API партнёров** | | | |
| 1   | Существует ли единая политика безопасности для интеграций с внешними системами (УК, поставщики ЖКУ, платёжная система, госорганы)? | Нет | Системы используют API управляющих компаний без единых политик безопасности. |
| 2   | Ведётся ли реестр внешних интеграций с владельцами, контрактами и классами передаваемых данных? | Нет | Системного контроля за передаваемыми данными нет. |
| 3   | Проходят ли контракты API проверку ИБ на минимизацию данных (передаются только необходимые поля, ПДн маскируются)? | Нет | Контракты API содержат категории данных, которые явно раскрывают ПДн. |
| 4   | Обеспечена ли изоляция данных разных партнёров (multi-tenancy): партнёр видит только свои ЖК и своих клиентов? | Нет | Партнёр из одной УК может увидеть или изменить данные клиентов и ЖК другой компании. |
| 5   | Используется ли единая точка входа (API Gateway) с аутентификацией партнёров (OAuth 2.0 Client Credentials, mTLS), авторизацией, rate limiting и валидацией схем? | Нет | Интеграции идут напрямую из tenant-core-app. Предлагаемая архитектура — в Task3. |
| 6   | Журналируются ли все запросы партнёров и передаваемые им данные с возможностью аудита? | Нет данных | |
| 7   | Заключены ли с партнёрами договоры поручения обработки ПДн (ч. 3 ст. 6 152-ФЗ) с требованиями к защите? | Нет данных | Партнёры получают ПДн собственников. Без поручения обработки это нарушение законодательства. |
| 8   | Проводится ли тестирование безопасности API (OWASP API Top 10, BOLA/IDOR) перед подключением нового партнёра? | Нет | Ошибки доступа к чужим данным обнаруживали сами команды разработки в ходе интеграции, а не проверки безопасности. |
| **VII. Организация ИБ и управление изменениями** | | | |
| 1   | Согласуются ли архитектурные решения и изменения в системах со специалистом по ИБ (security review в процессе изменений)? | Нет | Специалисту по ИБ передают не все решения и изменения: после смены руководителей процесс передачи информации нарушен. |
| 2   | Назначены ли ответственные за безопасность в продуктовых командах (Security Champions)? | Нет | Специалист по ИБ один на всю компанию, в составе функциональных команд роли ИБ нет. |
| 3   | Встроены ли проверки безопасности в CI/CD (SAST, DAST, сканирование зависимостей и образов, секретов)? | Нет данных | В командах есть DevOps-инженеры, проверить пайплайны. |
| 4   | Направлено ли уведомление в Роскомнадзор об обработке ПДн, есть ли модель угроз и утверждённые документы по 152-ФЗ (политика обработки ПДн, согласия)? | Нет данных | Компания не уверена, что все текущие бизнес-процессы соответствуют законодательству РФ. |
| 5   | Собираются ли согласия субъектов на обработку ПДн для каждой цели, включая аналитику и передачу партнёрам? | Нет данных | Без согласий на цели аналитики использовать ПДн в BI, ML и AI нельзя, данные нужно обезличивать. |
